# API reference

The API reference is generated from the packages' sources: every exported function, class,
interface, type, constant, member and signature, with its JSDoc. Each declaration's comment states
what it accepts and refuses (and with which error code or exception), its units and defaults,
who owns what it returns, and what the caller must dispose.

```sh
npm run build:packages
npm run api-reference      # writes api-reference/index.html
```

Every release carries it in `api-reference/` ([Release the packages](../how-to/release.md)).

## What the reference guarantees

`npm run api-reference` fails, naming each problem, when:

- a public declaration, member or signature has no JSDoc;
- a public declaration refers to a type the package does not export;
- a `{@link}` does not resolve;
- a published declaration file (`dist/**/*.d.ts`) states `any`. Values the framework does not
  look into (an endpoint's handle, a backend's container, an extension's state) are `unknown`.

`npm run check` runs it after the lint, and `npm run release` runs it too, so no release has an
undocumented public declaration.

The check covers `@swf/models` like every other package. Its types, fields, constructors and
functions are generated by lungo from the Lean models in `models/`, carrying each Lean docstring
across as JSDoc, so they are documented where they are proved: a missing docstring there fails the
check here.

## How windows are placed and drawn

A window stands in one room round the viewport's camera: its heading, its distance along the
floor and its height (`RoomPlace`, kept within `ROOM_LIMITS`), as
[ADR 0015](../adr/0015-one-room-with-windows-drawn-as-flat-cards.md) decides. Each view draws every
window as a card: a flat, upright rectangle centred where its projection places the window's
centre, the window's own size at `CARD_PIXELS_PER_UNIT` times a scale that follows its distance
along the floor (`cardScale`, `windowCard`). A projected fragment (`ProjectedFragment`) carries its
card, its scale and how the window is represented, and its surface's rectangle on the card.

A card shows no rotation. A window or surface that carries a rotation of its own (set by a host
through `node.patch` or `surface.patch`), or a surface whose geometry is not a `rect`, is drawn
upright as its rectangle, and the framework says so: the fragment's `geometricFidelity` is
`approximate`, its negotiation is `approximated`, and the DOM backend writes it on the element
(`data-swf-anchor`, `data-swf-shape`). A group's rotation moves the windows in it round the
camera. Snapshots of format `swf.workspace/1` are migrated to `swf.workspace/2`, which stands every
window and surface upright and names each in a warning.
